# Deploy and test BayamSafe for free

Everything below uses free tiers only, with no credit card required at the time of writing. Check each provider's current free-tier terms before you rely on them.

| Piece | Free service | What the free tier gives you |
| --- | --- | --- |
| Code + CI | GitHub + GitHub Actions | Tests run on every push ([ci.yml](../.github/workflows/ci.yml)) |
| App server | [Render](https://render.com) free web service | Docker deploy from the `staging` branch. **Sleeps after ~15 min without traffic**; the next request wakes it in about a minute |
| Database | [Neon](https://neon.tech) free Postgres | Always-free small Postgres, no expiry |
| Bot | Telegram (@BotFather) | Free |
| Payments | Built-in simulator, then [Campay](https://campay.net) sandbox | No real money moves |
| Keep-awake (optional) | [UptimeRobot](https://uptimerobot.com) free monitor | Pings `/api/health` every 5 min so Render doesn't sleep |

> Avoid Render's own free Postgres for anything you want to keep: it is deleted after 30 days. Neon (or Supabase) doesn't expire.

## Phase 0 — Test on your own computer (10 minutes, nothing to sign up for)

```bash
cd backend
npm install
npm test            # 70 tests, including a real Postgres engine (PGlite)
npm run build
node --env-file=.env.example dist/index.js
```

- Landing page: http://localhost:4000
- Checkout demo: the link printed in the console. Pay with any MTN or Orange number, then press **"Test mode: simulate approval"**.
- Admin: http://localhost:4000/admin, using the **demo admin key printed in the console** (it is new on every run).

> Your existing `backend/.env` uses old variable names (`PAYMENT_GATEWAY_PROVIDER`, `CAMPAY_APP_USERNAME`…). The app now reads the names in `.env.example` (`PAYMENT_PROVIDER`, `CAMPAY_USERNAME`…). Rename them before using that file.

## Phase 1 — Hosted staging with simulated payments (about 30 minutes)

### 1. Create the Telegram bot
1. In Telegram, open **@BotFather** → `/newbot` → name it e.g. *BayamSafe Staging* → username e.g. `bayamsafe_staging_bot`.
2. Copy the **token**. It is a password: never paste it in a chat, a commit or a screenshot.
3. Get **your own Telegram user id** from **@userinfobot**. This makes you the admin who receives review cards.

### 2. Create the database (Neon)
1. Sign up at neon.tech → create a project (region: Europe is closest to Cameroon).
2. Copy the **connection string**. It looks like `postgres://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
   The app creates its tables on first start.

### 3. Deploy on Render
1. Sign up at render.com with GitHub and allow access to the `bayam-safe` repo.
2. **New → Blueprint** → select the repo. Render reads [render.yaml](../render.yaml) and creates `bayamsafe-staging` on the free plan, deploying the `staging` branch.
3. When asked for values:
   - `DATABASE_URL`: the Neon string.
   - `TELEGRAM_BOT_TOKEN`: from BotFather.
   - `TELEGRAM_WEBHOOK_SECRET`: any long string using **only letters, digits, `_` and `-`** (Telegram rejects other characters). Generate one with `node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`.
   - `ADMIN_TELEGRAM_IDS`: your id from @userinfobot.
   - `PUBLIC_URL`: leave a placeholder for now (`https://example.com`).
4. After the first deploy, copy the service URL (`https://bayamsafe-staging-xxxx.onrender.com`), set it as `PUBLIC_URL` in **Environment**, and save. Render redeploys, and on start the app registers the Telegram webhook at `PUBLIC_URL/api/webhooks/telegram`.
5. `APP_SECRET` and `ADMIN_API_KEY` are generated by Render. Open **Environment** to read `ADMIN_API_KEY` for the dashboard.

### 4. Check it's alive
- `https://…onrender.com/api/health` → `{"status":"ok","storage":"postgres","payments":"simulated",…}`
- The landing page loads, and its buttons open your bot.
- Optional: an UptimeRobot HTTP monitor on `/api/health` every 5 minutes keeps it awake. One always-on service uses about 744 of Render's 750 free hours a month.

## Phase 2 — Test script (one phone and one computer are enough)

One Telegram account can be seller, rider **and** admin at the same time, so you can test alone. Use a second browser (or a private window) as the buyer.

**Seller sign-up**
1. Landing page → *Créer mon compte vendeur* → the bot opens → share your contact.
2. Go through all 8 steps (selfie, ID front and back, ID number, shop photo, shop location). Stop halfway with `/cancel`, send `/start`, and check that it resumes at the same step.
3. As admin you receive an album with the 4 photos, a location pin and approve/reject buttons. Reject with "Blurry": the seller gets the reason. Resubmit, then approve.
4. Open `/admin` → **Vérifications**, and use the selfie/ID slider on a new submission.

**Rider sign-up**
5. Send `/rider` (or use the landing-page *Devenir livreur* button) → complete the 9 steps → approve from Telegram or `/admin`.
6. You receive your rider number. From any account, `/verify BSR-XXXX` should show your selfie.
7. `/on_duty`, then share your **live location** (📎 → Location → Share live location).

**A full sale (escrow)**
8. Menu → *Nouvelle vente (même ville)* → item, price, fee, a buyer number, pickup → *Séquestre*.
9. Open the checkout link in the "buyer" browser → drop a GPS pin, record a voice note → enter a phone number → **Pay** → **Test mode: simulate approval**. The release code appears on this browser only. Open the same link elsewhere and the code must not show.
10. You (as rider) get the job offer → **Accept** → **Picked up** → **Enter buyer code**. Try a wrong code once, then the right one.
11. The order should show *Terminé* in the bot and `/admin`, and the ledger page must show **"Grand livre équilibré"**.

**Unhappy paths**
12. Report a problem from the checkout page → resolve it in `/admin` with *Rembourser le client*, and check the refund split.
13. Cash on delivery: create a COD sale with no rider deposit and check that the job is refused. Then add a deposit with `/topup 10000`. In simulated mode the bot replies with a test reference; approve it with `curl -X POST https://…onrender.com/api/dev/topups/<reference>/approve`, then accept the job again.
14. Inter-city: pick an agency route, record the waybill photo at drop-off, then mark *Bus arrivé* from the seller's order view.

Note any issue with the order's tracking code; `/admin` shows its full history and ledger entries.

## Phase 3 — Campay sandbox (real flows, no real money)

1. Create a free account at campay.net and open the **demo/sandbox** app in the dashboard.
2. Copy the app's API **username**, **password** and **webhook key**.
3. In the dashboard, set the webhook URL to `https://…onrender.com/api/webhooks/campay`.
4. In Render → Environment, set:
   ```
   PAYMENT_PROVIDER=campay
   CAMPAY_BASE_URL=https://demo.campay.net/api
   CAMPAY_USERNAME=…
   CAMPAY_PASSWORD=…
   CAMPAY_WEBHOOK_KEY=…
   ```
5. Repeat steps 8–11 with your own MoMo / Orange number. The sandbox has its own rules (for example, amount caps and test behaviour), so read them in the Campay dashboard and use small prices.
6. Check in Render's **Logs** that no `[webhook] rejected` lines appear. A rejected webhook means the webhook key doesn't match.

Things to confirm against Campay's current API docs during this phase: the field names in [campay.ts](../backend/src/payments/campay.ts) (`/collect/`, `/withdraw/`, `/transaction/{ref}/`, `external_reference`), and whether the webhook arrives as GET or POST (both are accepted).

## After deploying the edge-case sprint (Sprint 1)

This sprint adds no new environment variables. The new tables (sessions, audit journal and the rest) are created by the idempotent schema when the server starts, so there is no manual migration.

1. Deploy as usual (see above). Check `/api/health` is OK and that Render's logs show no schema errors on start.
2. Confirm the new background jobs are running. The server now schedules the timeouts job (every 5 min) and payment sync (every 2 min).
3. Create a prepaid test order and cancel it before paying, then again after paying: the second one must refund in full (simulated or sandbox payments).
4. Open an order as a rider, press "Client absent", and check the buyer gets the Telegram or checkout notice. Confirm "Retourner au vendeur" is refused before 15 minutes.
5. In `/admin`, open a disputed order and check the resolve, split, reassign and resend-code actions appear, and that the action shows in the audit journal.
6. Check `/earnings` and `/retrait` answer in the rider bot.
7. Check the ledger (`/api/admin/ledger`) still sums to 0.
8. Check that the landing page FAQ and the "Protection pour tous" block render in both French and English.

Roll back by redeploying the previous version; the new tables are additive and harmless to the old code.
